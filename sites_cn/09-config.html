第 09 章 · 边缘层

配置与命令路由

nanobot 的「用户界面」不只有 WebUI——还有 ~/.nanobot/config.json 和聊天里的 slash 命令。 这一章读透 Pydantic 配置模型（camelCase 兼容、环境变量、迁移与加载）和 CommandRouter 三层路由表，理解配置如何从磁盘进入运行时，以及 /stop 为什么能在会话锁之外立即生效。

一、根配置模型 Config(BaseSettings)

所有配置的顶层容器是 Config（schema.py:431）。 它把 agent、渠道、Provider、工具等子系统各自聚合成一个字段—— CLI、Gateway、WebUI 都通过 load_config() 拿到同一个对象。 

class Config(BaseSettings):
    """Root configuration for nanobot."""

    agents: AgentsConfig = Field(default_factory=AgentsConfig)
    channels: ChannelsConfig = Field(default_factory=ChannelsConfig)
    transcription: TranscriptionConfig = Field(default_factory=TranscriptionConfig)
    providers: ProvidersConfig = Field(default_factory=ProvidersConfig)
    api: ApiConfig = Field(default_factory=ApiConfig)
    gateway: GatewayConfig = Field(default_factory=GatewayConfig)
    tools: ToolsConfig = Field(default_factory=ToolsConfig)
    model_presets: dict[str, ModelPresetConfig] = Field(
        default_factory=dict,
        validation_alias=AliasChoices("modelPresets", "model_presets"),
        serialization_alias="modelPresets",
    )

注意 model_presets 已经用了显式 alias——这是根级字段里 「读多种键名、写固定键名」模式的预览，下面会看到更多例子。

二、camelCase 双命名兼容

配置 DTO 的公共基类是 config_base.py 里的 Base（不是 Pydantic v2 自带的 BaseModel 配置名，而是项目自定义的模型基类）： 

class Base(BaseModel):
    """Base model that accepts both camelCase and snake_case keys."""

    model_config = ConfigDict(alias_generator=to_camel, populate_by_name=True)
◆ 核心要点

alias_generator=to_camel：序列化/反序列化时，JSON 键用 camelCase（前端友好）。 Python 属性仍写 snake_case（PEP 8）。 populate_by_name=True：解析时两种键名都能接受—— 既可以用 sessionTtlMinutes，也可以用 session_ttl_minutes 构造模型。

字段级 alias：配置演进与向后兼容

全局 camelCase 生成器解决不了「改名后旧配置文件还能读」的问题。 这时在字段上显式声明 validation_alias 和 serialization_alias： 

    session_ttl_minutes: int = Field(
        default=15,
        ge=0,
        validation_alias=AliasChoices("idleCompactAfterMinutes", "sessionTtlMinutes"),
        serialization_alias="idleCompactAfterMinutes",
    )  # Auto-compact idle threshold in minutes (0 = disabled)
? 为什么这样设计

读：idleCompactAfterMinutes（旧名）和 sessionTtlMinutes（过渡名）都认。 写：save_config() 只输出 idleCompactAfterMinutes（新 canonical 键）。 用户升级 nanobot 后不必立刻改配置文件；保存一次就自动迁移键名。 这是「配置演进」的标准模式——比硬 breaking change 温和得多。

三、环境变量覆盖

Config 继承 BaseSettings，环境变量前缀与嵌套分隔符在 model_config 里声明： 

    model_config = SettingsConfigDict(
        env_prefix="NANOBOT_",
        env_nested_delimiter="__",
    )

嵌套字段用双下划线展开。例如覆盖默认模型： 

export NANOBOT_AGENTS__DEFAULTS__MODEL="gpt-4o"
export NANOBOT_TOOLS__RESTRICT_TO_WORKSPACE="true"
✓ 实用提示

复杂嵌套值（如整个 mcpServers 对象）可以用 JSON 字符串作为环境变量值。 若解析失败，load_config() 在无配置文件时会抛出带明确提示的 ConfigLoadError（loader.py:63-69）。

四、配置路径与加载流程

4.1 路径：get_config_path()

def get_config_path() -> Path:
    """Get the configuration file path."""

        return _current_config_path
    return Path.home() / ".nanobot" / "config.json"

4.2 load_config() 主流程

def load_config(config_path: Path | None = None) -> Config:
    """
    Load configuration from file or create default.

    Args:
        config_path: Optional path to config file. Uses default if not provided.

    Returns:
        Loaded configuration object.
    """
    global _schema_refs_ready
    if not _schema_refs_ready:
        _resolve_tool_config_refs()
        _schema_refs_ready = True

    path = config_path or get_config_path()

    if not path.exists():
        try:
            config = Config()
        except SettingsError as exc:
            raise ConfigLoadError(
                path,
                kind="invalid_schema",
                summary=(
                    "Environment-based configuration could not be parsed. "
                    "Check that complex NANOBOT_* values use valid JSON."
                ),
            ) from exc
        except ValidationError as exc:
            raise ConfigLoadError(
                path,
                kind="invalid_schema",
                summary="Environment-based configuration is invalid.",
                issues=validation_issues(exc),
            ) from exc
        _apply_ssrf_whitelist(config)
        return config

    try:
        with path.open(encoding="utf-8") as handle:
            data = json.load(handle)
    except json.JSONDecodeError as exc:
        raise ConfigLoadError(
            path,
            kind="invalid_json",
            summary=(
                f"JSON syntax error at line {exc.lineno}, column {exc.colno}: "
                f"{_sentence(exc.msg)}"
            ),
        ) from exc
    except UnicodeDecodeError as exc:
        raise ConfigLoadError(
            path,
            kind="io_error",
            summary="The file is not valid UTF-8.",
        ) from exc
    except OSError as exc:
        detail = exc.strerror or type(exc).__name__
        raise ConfigLoadError(
            path,
            kind="io_error",
            summary=f"Unable to read the file: {_sentence(detail)}",
        ) from exc

    if not isinstance(data, dict):
        root_type = type(data).__name__
        raise ConfigLoadError(
            path,
            kind="invalid_root",
            summary="The top level of config.json must be a JSON object.",
            issues=(
                ConfigIssue(
                    path=(),
                    message=f"Expected an object, but found {root_type}.",
                ),
            ),
        )

    data = _migrate_config(cast(dict[str, Any], data))
    try:
        config = Config.model_validate(data)
    except ValidationError as exc:
        issues = validation_issues(exc)
        raise ConfigLoadError(
            path,
            kind="invalid_schema",
            summary=f"Found {len(issues)} invalid setting(s).",
            issues=issues,
        ) from exc

    _apply_ssrf_whitelist(config)
    return config

4.3 旧格式迁移 _migrate_config()

def _migrate_config(data: dict[str, Any]) -> dict[str, Any]:
    """Migrate old config formats to current."""
    # Move tools.exec.restrictToWorkspace → tools.restrictToWorkspace
    tools_value = data.get("tools", {})
    if not isinstance(tools_value, dict):
        return data
    tools = cast(dict[str, Any], tools_value)
    exec_cfg = _as_config_object(tools.get("exec", {}))
    if (
        exec_cfg is not None
        and "restrictToWorkspace" in exec_cfg
        and "restrictToWorkspace" not in tools
    ):
        tools["restrictToWorkspace"] = exec_cfg.pop("restrictToWorkspace")

    # Move tools.myEnabled / tools.mySet → tools.my.{enable, allowSet}.
    # The old flat keys shipped in the initial MyTool landing; wrapping them in a
    # sub-config keeps `web` / `exec` / `my` symmetric and gives room to grow.
    if "myEnabled" in tools or "mySet" in tools:
        my_cfg = tools.get("my")
        if my_cfg is None:
            my_cfg = {}
            tools["my"] = my_cfg
        if not isinstance(my_cfg, dict):
            return data
        my_cfg = cast(dict[str, Any], my_cfg)
        if "myEnabled" in tools and "enable" not in my_cfg:
            my_cfg["enable"] = tools.pop("myEnabled")
        else:
            tools.pop("myEnabled", None)
        if "mySet" in tools and "allowSet" not in my_cfg:
            my_cfg["allowSet"] = tools.pop("mySet")
        else:
            tools.pop("mySet", None)

    return data

4.4 递归补默认值 merge_missing_defaults()

def merge_missing_defaults(existing: object, defaults: object) -> object:
    """Recursively add missing defaults without replacing configured values."""
    if not isinstance(existing, dict) or not isinstance(defaults, dict):
        return cast(object, existing)

    existing_dict = cast(dict[str, object], existing)
    defaults_dict = cast(dict[str, object], defaults)
    merged = dict(existing_dict)
    for key, value in defaults_dict.items():
        if key not in merged:
            merged[key] = value
        else:
            merged[key] = merge_missing_defaults(merged[key], value)
    return merged
? 为什么需要 merge_missing_defaults

新版本可能在 schema 里新增配置项并给出默认值。 老用户的 config.json 里没有这些键——直接覆盖会把用户已有设置冲掉； 完全不管又会让新功能缺省行为不一致。 merge_missing_defaults 只补缺失键，不覆盖已配置值， 实现平滑升级。

4.5 ${VAR} 环境变量引用

resolve_config_env_vars()（loader.py:194）遍历整个 Config 对象，把字符串里的 ${VAR} 替换成环境变量值； 缺失则抛 ConfigLoadError（kind=missing_env）。 单字段懒解析用更宽松的 resolve_env_refs()（loader.py:224）—— 变量未设置时返回空字符串，适合 API key 等「未配置 = 禁用」的场景。

4.6 保存：写回 camelCase

save_config()（loader.py:144）用 config.model_dump(mode="json", by_alias=True) 序列化， 再经 _write_text_atomic 原子写入——崩溃 mid-write 不会留下截断的 JSON。

五、命令路由三层表

CommandRouter（command/router.py）是纯字典路由—— 没有正则引擎，没有插件扫描，注册表在 register_builtin_commands() 里一次性填好。 

class CommandRouter:
    """Pure dict-based command dispatch.

    Three tiers checked in order:
      1. *priority* — exact-match commands handled before the dispatch lock
         (e.g. /stop, /restart).
      2. *exact* — exact-match commands handled inside the dispatch lock.
      3. *prefix* — longest-prefix-first match (e.g. "/team ").
    """

    def __init__(self) -> None:
        self._priority: dict[str, Handler] = {}
        self._exact: dict[str, Handler] = {}
        self._prefix: list[tuple[str, Handler]] = []
用户输入 "/model fast" │ ▼ normalize_command_text() ← 剥 @bot 后缀 │ ├─ priority 精确匹配？ /stop /restart /status │ └─ 是 → dispatch_priority()，不经会话锁 │ ├─ exact 精确匹配？ /new /help /dream … │ ├─ prefix 最长前缀？ /model /goal /history … │ └─ 以 / 开头但都不中 → fuzzy match 提示 + /help

5.1 群聊命令归一化

def normalize_command_text(text: str) -> str:
    """Normalize slash-command transport variants before routing.

    Telegram and Discord-style command dispatch can produce ``/cmd@bot args``.
    The bot suffix belongs to the transport, not the command name, so strip it
    once at the router boundary while preserving user arguments verbatim.
    """
    stripped = text.strip()
    if not stripped.startswith("/"):
        return stripped
    first, sep, rest = stripped.partition(" ")
    if "@" not in first:
        return stripped
    command, suffix = first.rsplit("@", 1)
    if command and suffix and _BOT_SUFFIX_RE.fullmatch(suffix):
        return f"{command}{sep}{rest}" if sep else command
    return stripped

5.2 dispatch() 与无效命令提示

    async def dispatch(self, ctx: CommandContext) -> OutboundMessage | None:
        """Try exact and prefix handlers, then reject invalid slash commands."""
        ctx.raw = normalize_command_text(ctx.raw)
        cmd = ctx.raw.lower()

        if handler := self._exact.get(cmd):
            return await handler(ctx)

        for pfx, handler in self._prefix:
            if cmd.startswith(pfx):
                ctx.args = ctx.raw[len(pfx):]
                return await handler(ctx)

        return self._invalid_command_response(ctx)

_invalid_command_response()（router.py:125）用 difflib.get_close_matches 做模糊匹配—— 输入 /hel 会提示 Did you mean "/help"?。 这保证所有以 / 开头的消息都不会漏进 LLM， 避免模型把无效命令当成普通对话。

▲ 易错点：priority 与 exact 的重复注册

/status 同时注册在 priority 和 exact（builtin.py:1025-1027）。 活跃会话有 pending queue 时，用户发 /status 走 priority 路径立即响应； 空闲时走 turn pipeline 的 command 阶段也能响应。 设计意图是「状态查询不应被会话锁卡住」——与 /stop 同类。

六、AgentLoop 侧的三个入口

命令不是单独的服务——AgentLoop 在三个时机调用 CommandRouter，对应不同的并发语义（详见第 03 章 的会话锁与 pending queue）：

检查方法调用时机处理器
is_priority(raw) run() 六道分流第 3 层（loop.py:1189） dispatch_priority——不经 dispatch lock
is_dispatchable_command(raw) 会话已有 pending queue 时（loop.py:1217） dispatch——inline，不排队注入
turn pipeline command 阶段 正常回合的七阶段流水线（loop.py:1543） _dispatch_command → commands.dispatch 
    async def _dispatch_command(self, ctx: TurnContext) -> bool:
        if ctx.kind is TurnKind.SYSTEM:
            return False
        session = ctx.require_session()
        raw = ctx.msg.content.strip()
        _, automation_metadata = automation_history_overrides(ctx.msg.metadata)
        is_user_turn = (
            ctx.original_user_text is not None
            and not automation_metadata
            and ctx.msg.channel != "system"
            and ctx.msg.sender_id != "subagent"
        )
        cmd_ctx = CommandContext(
            msg=ctx.msg,
            session=session,
            key=ctx.session_key,
            raw=raw,
            loop=self,
            runtime=ctx.runtime,
            is_user_turn=is_user_turn,
            turn_scopes=ctx.turn_scopes,
        )
        result = await self.commands.dispatch(cmd_ctx)
◆ 核心要点：/stop 为何必须在锁外

第 03 章 讲过：同一会话同时只能有一个 _dispatch 任务。如果 /stop 也要等锁，用户就无法取消正在运行的回合—— 形成死等。所以 /stop、/restart 走 priority 层，在 dispatch_priority 里直接 _cancel_active_tasks 并 drain pending queue（builtin.py:202-216）。

八、练习

基础用户在 Telegram 群聊发送 /model fast@my_nanobot_bot。 路由层最终看到的 ctx.raw 是什么？为什么不在渠道层处理？

最终 ctx.raw = /model fast。

normalize_command_text()（router.py:23-39）在路由边界统一处理： 把 /model@my_nanobot_bot 剥成 /model，参数 fast 原样保留。

不在渠道层处理的原因：@bot 后缀是传输层细节（Telegram/Discord 特有）， 18 个渠道不应各自实现一遍。集中在 router 一处，所有渠道的命令语义保持一致。

进阶老配置文件里有 tools.exec.restrictToWorkspace: true， 但没有顶层的 tools.restrictToWorkspace。加载后这两个键分别是什么状态？

_migrate_config()（loader.py:347-358）在 Config.model_validate 之前运行：把 tools.exec.restrictToWorkspace 移动到 tools.restrictToWorkspace，并从 exec 子对象中删除。

加载完成后：内存中 config.tools.restrict_to_workspace == True（Python snake_case）； 若调用 save_config()，磁盘 JSON 写 tools.restrictToWorkspace: true， 旧的嵌套键不再出现。

挑战某会话正在执行一个 30 秒的工具调用。 用户连发 /stop 和 /help。请说明两条命令各自走哪条入口、 能否打断工具调用、以及 /help 的响应会不会进入 LLM 上下文。

/stop

  • 入口：run() → is_priority → dispatch_priority（loop.py:1189-1193）
  • 不经会话锁；cmd_stop 调用 _cancel_active_tasks 并 drain pending queue（builtin.py:206-215）
  • 能否打断工具：取决于 runner 对 CancelledError 的处理——stop 会取消 dispatch 任务，正在 await 的工具可能收到取消信号

/help

  • 若 pending queue 已存在：is_dispatchable_command → inline dispatch（loop.py:1217-1221）
  • 否则走 turn pipeline 的 command 阶段 → _dispatch_command
  • shortcut 命令会 _persist_user_message_early(..., _command=True)（loop.py:1707-1708）， 写入会话但 get_history 会过滤 _command 标记——不进 LLM 上下文
本章小结

配置层 = Pydantic camelCase 双命名 + loader 迁移/加载/原子保存； 命令层 = priority / exact / prefix 三层路由 + AgentLoop 三入口。 下一章进入安全边界：工作区围栏、SSRF、shell 沙箱与违规升级策略。
