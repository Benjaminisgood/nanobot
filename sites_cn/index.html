一、nanobot 是什么

nanobot 是一个轻量级开源 AI Agent 框架：Python 后端 + React/TypeScript WebUI。它的核心是一个 很小的 agent 循环——从聊天渠道接收消息、调用 LLM、执行工具、管理会话记忆，然后把回复送回渠道。

它最值得学习的地方不是"功能多"，而是它在 .agent/design.md 里明确写下并真正执行了一条架构纪律：

核心设计约束（Core stays small; extend at the edges）

新能力应该通过 channels/、tools/、skills 或 MCP server 添加。 agent/loop.py 和 agent/runner.py 构成关键核心路径，对它们的改动必须最小且有充分理由。 如果一个特性可以放在渠道适配器、工具或外部 MCP server 里，就不应该内联进 agent 循环。

—— 原文见 .agent/design.md。这条纪律解释了本项目 90% 的目录结构决策，也是你读代码时最重要的地图。

规模速览

CORE

~4000 行

agent/loop.py (2344) + agent/runner.py (1670) 是全部核心链路。读懂这两个文件，就读懂了 nanobot。

EDGES

18 个渠道

Telegram、Discord、Slack、飞书、Matrix、企业微信、钉钉、邮件…… 全部自动发现，互不依赖。

TOOLS

26 个模块

文件系统、shell、搜索、web、MCP、cron、subagent、图片生成…… 全部通过 pkgutil 扫描注册。

PROVIDERS

10+ 后端

Anthropic、OpenAI 兼容、OpenAI Responses、Azure、Bedrock、Copilot、Codex、xAI…… 共享一个 2 方法抽象基类。

STYLE

Python 3.11+

全异步（asyncio），行宽 100，ruff 检查 E/F/I/N/W，basedpyright 严格类型检查。

CONFIG

单文件配置

~/.nanobot/config.json，Pydantic 模型 + camelCase 别名，支持 ${ENV} 引用。

三、环境准备

先把项目跑起来，读代码时才能随时下断点验证。以下命令来自仓库 AGENTS.md：

# 安装依赖（含所有 extras 与开发依赖）
uv sync --all-extras --dev

# 跑单个测试 / 全部测试
pytest tests/test_openai_api.py::test_function -v
pytest

# 代码检查
ruff check nanobot/

# 严格类型检查（与 CI 一致）
uv run --no-sync python -m scripts.install_channel_dependencies --all-channels
uv run --no-sync basedpyright

# 启动网关（会同时提供 WebUI 与 API）
nanobot gateway

# WebUI 开发（把 /api、/webui、/auth 与 WebSocket 代理到网关 :8765）
cd webui && bun run dev
cd webui && bun run build   # 产物输出到 ../nanobot/web/dist
cd webui && bun run test
读源码前建议先做的一件事

在 nanobot/agent/loop.py 的 _run_turn_stage 里已经有 stage 级别的 logger.debug 埋点。把日志级别调到 DEBUG，发一条消息，你会直接看到七个 stage 的耗时序列—— 这是理解第 03 章最快的方式。
