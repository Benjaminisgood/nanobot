OpenAI 兼容 HTTP API

把 nanobot 接到现有 Chat Completions 客户端（Cursor、脚本、别的 bot）时， 走的是 nanobot/api/server.py：还是同一个 AgentLoop， 只是入口从 publish_inbound 换成了 process_direct。

一、三件路由 + 可选 Bearer

def create_app(
    agent_loop: "AgentLoop",
    model_name: str = "nanobot",
    request_timeout: float = 120.0,
    api_key: str = "",
) -> web.Application:
    """Create the aiohttp application.

    Args:
        agent_loop: An initialized AgentLoop instance.
        model_name: Model name reported in responses.
        request_timeout: Per-request timeout in seconds.
        api_key: Optional API key for Bearer-token authentication on API routes.
    """
    app = web.Application(client_max_size=20 * 1024 * 1024)  # 20MB for base64 images
    app[_AGENT_LOOP_KEY] = agent_loop
    app[_MODEL_NAME_KEY] = model_name
    app[_REQUEST_TIMEOUT_KEY] = request_timeout
    app[_SESSION_LOCKS_KEY] = {}  # per-user locks, keyed by session_key

注册的路径：POST /v1/chat/completions、GET /v1/models、GET /health。

    @web.middleware

◆ 核心要点

hmac.compare_digest 做常量时间比较，避免 API key 被计时攻击逐字节猜。 api_key 为空则整站不鉴权——只适合本机。 健康检查永远免密，方便编排探测。

二、不进 inbound 队列：process_direct

? 为什么 API 还要自己的锁

process_direct 仍会进 _process_message，用 loop 里的会话锁。 HTTP 层这把锁是为了同一个 api session 的两次 POST 不要交错写 SSE—— 客户端连发两个 stream=true 时，先完成的那个才写 resp。 和聊天侧「pending 注入队列」是不同的产品语义：HTTP 调用通常期望请求/响应对齐。

_on_stream_end 故意什么都不做：注释写明工具回合之后生成还会继续， HTTP SSE 只能在 process_direct 返回时关闭。 这和第 14 章渠道侧「segment end ≠ 整轮结束」是同一事实的 HTTP 表述。

若整轮没流出任何 token（模型直接给完整 content），finally 前会把 _response_text(response) 补进队列，避免 stream=true 的客户端拿到空流。

▲ 易错点：model 字段不能随便填

body 里的 model 若存在且不等于网关配置的 model_name，直接 400。 这个 API 不是多模型路由器，只是「当前 AgentLoop 的外壳」。 换模型走 nanobot 自己的 preset / /model，不是 OpenAI 的 model: 参数。

四、练习

基础不配 API key 时，局域网里别人能不能打你的 /v1/chat/completions？

中间件在 if not api_key: return await handler(request)。 绑定 0.0.0.0 且无 key = 谁都能驱动你的 agent（含 exec）。 本机试用可以；暴露到网络必须设 key，并配合防火墙。

进阶为什么 API 不 publish_inbound 再等 outbound？列两条理由。

1. 请求/响应要对齐。 HTTP 调用方阻塞在这一次 POST 上，需要这次的最终文本/SSE。 总线是多生产者多消费者，把「第 N 个 inbound」和「第 M 个 outbound」配对容易配错。

2. 避免和聊天调度搅在一起。 AgentLoop.run() 的 1 秒超时心跳、 优先命令、注入队列都是为 IM 设计的。API 用 process_direct 同步跑完七阶段，语义更简单。

挑战客户端 stream: true，模型先吐 20 个 token，再调用 exec 30 秒，再吐结尾。SSE 连接何时结束？工具期间连接上会怎样？

连接在 process_direct 整段返回后才结束（_on_stream_end 不关流）。 工具那 30 秒客户端可能暂时收不到 data 行（或只有心跳，若有的话——这段实现主要靠 TCP 挂着）。 前 20 个 token 已经作为 SSE chunk 发出；结尾再发。 这与 Chat Completions 常见「工具期间静默」行为一致，不要误判为超时就掐掉—— 真正的超时是外层 asyncio.wait_for(..., timeout_s)。
