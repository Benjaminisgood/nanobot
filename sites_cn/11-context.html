系统提示与 Skills

第 03 章的 build 阶段会调用 ContextBuilder.build_messages()。 这一章拆开那一步：模型每一轮真正看到的 system prompt 是怎么拼出来的， 以及 Skills 如何做到「目录进提示、正文按需加载」。

一、system prompt 的分层栈

ContextBuilder（agent/context.py）不负责对话历史——历史来自 session.get_history()（07 章）。 它只组装每轮都会重建的那一段 system 文本：

build_system_prompt() 1. identity.md 身份 + 工作区路径 + 平台策略 2. AGENTS.md / SOUL.md / USER.md 项目与人格 bootstrap 3. tool_contract.md 工具使用契约 4. MEMORY.md 长期记忆（若已定制） 5. Active Skills always=true 或用户 $skill-name 点名的全文 6. skills_section.md 其余技能的「目录摘要」 7. Recent History history.jsonl 里 Dream 尚未消化的条目 8. [Archived Context Summary] 本轮 compact 留下的会话摘要 各段用 "---" 连接，再作为 role=system 的第一条消息。

拼装顺序就写在这一个函数里：

    def build_system_prompt(
        self,
        *,
        active_skill_names: Sequence[str] | None = None,
        channel: str | None = None,
        session_summary: str | None = None,
        workspace: Path | None = None,
        include_memory: bool = True,
        include_memory_recent_history: bool = True,
        session_key: str | None = None,
        unified_session: bool = False,
    ) -> str:
        """Build the system prompt from identity, bootstrap files, memory, and skills."""
        root = workspace or self.workspace
        parts = [self._get_identity(channel=channel, workspace=root)]

        bootstrap = self._load_bootstrap_files(root)
        if bootstrap:
            parts.append(bootstrap)

        parts.append(render_template("agent/tool_contract.md"))

        if include_memory:
            memory = self.memory.read_memory()
            if memory and not self._is_template_content(memory, "memory/MEMORY.md"):
                parts.append(f"# Memory\n\n## Long-term Memory\n{memory}")
◆ 核心要点

system prompt 不是一份写死的常量。它每轮根据工作区文件、Dream 进度、 用户有没有写 $cron 这类引用而变化。这也是为什么 build 阶段必须在 run 之前：Runner 拿到的 initial_messages[0] 已经是本轮定制过的提示。

二、Bootstrap 文件：人格写在工作区里

三个文件名写在类常量 BOOTSTRAP_FILES 里，但加载时根目录并不相同： 

    def _load_bootstrap_files(self, workspace: Path | None = None) -> str:
        """Load project instructions plus the agent's global profile files."""
        parts: list[str] = []
        project_root = workspace or self.workspace
        sources = [
            ("AGENTS.md", project_root),
            ("SOUL.md", self.workspace),
            ("USER.md", self.workspace),
        ]

        for filename, root in sources:
            file_path = root / filename
            if file_path.exists():
                content = file_path.read_text(encoding="utf-8")
                if filename == "SOUL.md" and self._is_template_content(
                    content,
                    "legacy/SOUL.md",
                ):
                    content = load_bundled_template("SOUL.md") or content
                if not content.strip():
                    continue
                if filename in self._SKIPPABLE_DEFAULTS and self._is_template_content(
                    content, filename
                ):
                    continue
                parts.append(f"## {filename}\n\n{content}")
文件读取根含义
AGENTS.mdproject_root（当前会话工作区）这个项目的操作手册，随项目走
SOUL.mdself.workspace（agent 全局工作区）人格 / 价值观，Dream 会改它
USER.md同上全局工作区关于用户的长期笔记
▲ 易错点：未定制的模板会被跳过

_SKIPPABLE_DEFAULTS = {"AGENTS.md", "USER.md"}。 如果文件内容和打包模板逐字相同，_is_template_content 为真，这段不会进 prompt。 避免把「还没写过的占位文档」浪费上下文窗口。 SOUL.md 走另一条路：若仍是 legacy 模板，会换成打包的新模板再注入。

三、Skills：目录进提示，正文按需加载

Skill 是带 YAML frontmatter 的 SKILL.md，目录结构是 skills/<name>/SKILL.md。查找顺序：工作区覆盖内置——同名时工作区赢。

两种进入 prompt 的方式

Always-on：frontmatter 里 always: true（或 nanobot 元数据块里的 always）。

    def get_always_skills(self) -> list[str]:
        """Get skills marked as always=true that meet requirements."""
        return [
            entry["name"]
            for entry in self.list_skills(filter_unavailable=True)
            if (meta := self.get_skill_metadata(entry["name"]) or {})
            and (
                self._parse_nanobot_metadata(meta.get("metadata")).get("always")
                or meta.get("always")
            )
        ]

显式点名：用户消息里写 $cron、$github。正则是 $ 后跟标识符：

    def get_explicitly_invoked_skills(self, text: str) -> list[str]:
        """Resolve ``$skill-name`` references to enabled, available skills."""
        if not text:
            return []
        available = {
            entry["name"]
            for entry in self.list_skills(filter_unavailable=True)
        }
        invoked: list[str] = []
        for match in _SKILL_REFERENCE.finditer(text):
            name = match.group(1)
            if name in available and name not in invoked:
                invoked.append(name)
        return invoked

调用点在 build_messages()（context.py:238-241）：只有当前消息 role == "user" 时才扫描。点名的 skill 全文进 # Active Skills；其余 skill 只出现在摘要里。

? 为什么不全文塞进每一次请求

内置 skills 有 cron、github、image-generation、weather……全部正文会吃掉几千 token。 摘要告诉模型「有这个技能、描述是什么、文件在哪」，模型需要细节时用 read_file 去读 SKILL.md。这就是注释里说的 progressive loading（skills.py:132-133）。

不可用的 skill（缺二进制、缺环境变量）仍会出现在摘要里，但带 (unavailable: …) 后缀，避免模型去调用做不到的能力。

四、拼成 messages 列表

build_messages() 把 system + history + 当前用户消息拼在一起。 若 history 最后一条已经是 user，就把当前内容合并进去，而不是再 append—— 防止 OpenAI 兼容接口拒绝「连续两条 user」。 这和第 04 章 Runner 注入队列时的合并是同一条不变量。

✓ 实用提示

想看某一轮真正送给模型的 system prompt：在 AgentLoop._build_initial_messages（loop.py:721）下断点， 打印 initial_messages[0]["content"][:2000]。 比猜「配置里哪一项生效了」快得多。

五、练习

基础用户工作区里的 AGENTS.md 还是安装时拷出来的默认模板，一字未改。它会进入 system prompt 吗？

不会。

AGENTS.md 在 _SKIPPABLE_DEFAULTS 里。 _is_template_content(content, "AGENTS.md") 为真时 continue。 改一个字就会注入。这是为了省 token，不是 bug。

进阶用户发「帮我看看 $cron 和 $cron」。Active Skills 里会出现几次 cron 全文？

一次。

get_explicitly_invoked_skills 用 name not in invoked 去重， 再交给 load_skills_for_context。always 列表里若已有 cron， build_system_prompt 的 extend 循环也会跳过重复名。

挑战为什么 AGENTS.md 从 project_root 读，而 SOUL.md 从 self.workspace 读？如果两个路径相同会发生什么？

多项目 / 多工作区时，agent 全局人格（SOUL、USER、Dream 维护的 MEMORY）应跨项目稳定； 当前项目的操作手册（AGENTS.md）应随 WorkspaceScope.project_path 变化。

默认单工作区时两者相同，三个文件都从 ~/.nanobot/workspace/ 读，行为退化成「一堆 markdown 进 prompt」。 这是有意的：简单部署零配置，复杂部署才显现路径分叉。
